# 天谕手游营销工作台 Supabase MVP 规格

## 目标

把当前单机体验版改为可登录、多人共用同一套在线数据的 MVP，同时保留现有成员工作台与主营总台的功能和联动关系。现有 SQLite 示例数据不迁移，Supabase 从空数据开始。

## 使用范围

- 只支持一个团队：天谕手游营销团队。
- 角色只有 `admin`（主营）和 `member`（成员）。MVP 只有一位主营。
- 只面向电脑浏览器。
- 后续部署上线时继续使用同一套 Supabase 数据库。

## 账号系统

- 登录方式：用户名 + 密码。用户名由 3–32 位英文字母、数字、点、下划线或短横线组成，登录时不区分大小写。
- Supabase Auth 继续使用其原生 Email + Password 能力，但邮箱仅作为系统内部标识：`<标准化用户名>@users.tianyu.invalid`；界面与成员数据中不展示邮箱。
- 账号只能由主营创建；创建时直接填写显示姓名、岗位、登录用户名和初始密码。
- Supabase Auth 用户创建时将内部邮箱标记为已确认，不发送邮件或短信。
- 首次登录不强制修改密码。
- 忘记密码由主营直接重置。
- 成员离队后停用账号，禁止继续登录，历史工作数据保留。
- 浏览器端只保存 Supabase 会话，不保存明文密码。

## 权限

### 成员

- 查看已发布的版本、目标、节点、排期、卖点和自己的热点数据。
- 只查看自己的任务和步骤。
- 对主营分配的任务，只能修改状态与个人步骤。
- 可以创建、修改、删除自己的个人待办。
- 个人待办可关联已发布的目标、版本和版本节点。
- 删除个人待办后，立即从目标、节点和统计中移除。
- 查看自己的当前统计和最近 12 个月历史趋势。

### 主营

- 管理成员账号：创建、重置密码、停用、恢复。
- 管理并发布版本、目标、节点、排期和卖点。
- 分配任务并编辑任务的业务字段。
- 查看全团队任务与步骤进度，可按成员和版本筛选。
- 查看全团队历史趋势，也可按成员或版本筛选。

## 模块联动

- 任务状态改变后，立即更新个人工作台的任务统计。
- 关联目标的任务完成或撤销完成后，重新计算目标完成率。
- 关联节点的任务全部完成后，节点自动完成；任何任务撤销完成后，节点回到未完成。
- 排期发布生成的制作与发布任务，其状态回写到排期阶段。
- 个人步骤只计算步骤进度，不自动修改任务状态，也不直接影响目标或节点。
- 成员修改任务或步骤后，主营团队看台通过 Supabase Realtime 更新。
- 版本名称、颜色或状态更新后，所有关联模块读取相同版本记录并同步显示。
- 有关联数据的版本不能直接删除；需要先解除关联。数据库外键禁止留下失效版本 ID。
- 卖点与热点雷达不自动生成任务。

## 草稿与发布

- 目标、节点、排期和卖点保留“草稿／已发布”机制。
- 新草稿对成员不可见。
- 已发布内容的修改在再次发布前，成员继续看到上一次发布内容。
- 排期发布后生成独立阶段任务，并保留现有的负责人、日期和个人步骤保护逻辑。

## 统计

- 当前统计：任务总数、未开始、进行中、已完成、已逾期、完成率。
- 支持按成员和版本统计。
- 每日生成统计快照，保留最近 12 个月。
- 成员只查看自己的当前统计和趋势。
- 主营查看团队统计，并可筛选成员或版本。
- 快照使用北京时间日期，每天凌晨生成；同一天重复执行应覆盖或跳过，不能产生重复记录。

## 热点雷达

- 抖音公开热榜与小红书竞品监控仍由主营电脑上的有头浏览器采集。
- 采集完成后上传到 Supabase；在线成员只读取结果，不在自己的电脑启动采集浏览器。
- 平台登录状态文件继续保存在主营本机，不上传 Cookie 或浏览器账号凭据。
- 热点结果按用户可见范围存储；MVP 的团队热点由主营采集并共享给团队。

## 安全约束

- 所有公开表启用 RLS；未登录用户不能读取业务数据。
- 浏览器仅使用 Supabase publishable key。
- secret/service role key 只放在服务端环境变量或 Supabase Edge Function，禁止进入前端与版本库。
- 管理账号和重置密码接口必须先验证调用者为启用状态的主营。
- 前端传来的用户 ID 不能作为权限依据，身份始终来自 Supabase JWT。

## 部署边界

- 本阶段先在本地运行并连接 Supabase 免费项目。
- 代码和 SQL migration 可直接用于后续线上部署。
- 本地 SQLite 示例数据库保留为开发备份，但 Supabase 模式启用后不再作为多人业务数据源。
