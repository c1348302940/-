# 《天谕》手游营销工作台 · 单机体验版

面向网易雷火《天谕》手游营销部门的本地工作台。主营销发布公共信息与分配工作，成员在一处看清自己全部未开始／进行中／已完成的工作。

单机体验版：用「成员／主营」视角切换体验，不做工作台账号登录；数据保存在本机，重启后仍在。
完整需求见上级目录的 `营销工作台产品说明书.md`。

## 一、运行方式

### 环境要求

| 项目 | 要求 | 本机验证环境 |
|---|---|---|
| Node.js | **≥ 22.5**（需要内置 `node:sqlite`；推荐 24 LTS） | v24.19.0 |
| npm | 任意近期版本 | 11.17.0 |
| 浏览器 | Chrome / Edge 等桌面浏览器 | Chromium（Playwright 自带） |
| 操作系统 | Windows / macOS / Linux | Windows 11 |

> 数据库使用 Node 内置的 `node:sqlite`，**不需要**任何原生编译依赖。启动时会打印 `ExperimentalWarning: SQLite is an experimental feature`，属正常提示，不影响使用。

### 安装与启动

Windows 可直接双击工作台文件夹中的 **`启动营销工作台.cmd`**。它会启动本机服务（如尚未运行），并在默认浏览器打开工作台。
不要直接双击 `app/public/index.html`，浏览器无法从本地文件载入工作台数据。

```bash
cd app
npm install          # 仅用于热点雷达的 Playwright；核心工作台零外部依赖
npm start            # 启动本地服务
```

启动后终端会打印：

```
《天谕》手游营销工作台 · 单机体验版
已启动：http://127.0.0.1:8787
数据文件：<...>/app/data/app.db
```

浏览器打开 **http://127.0.0.1:8787** 即可。服务只监听 `127.0.0.1`，不对局域网或公网开放。
端口可用环境变量覆盖：`PORT=9000 npm start`。

首次启动会自动载入一套**明确标注「示例」**的演示数据（3 个并行版本、4 位体验成员、13 项任务、目标／节点／排期／卖点各若干），用于验证个人任务隔离与并行版本。

### 常用命令

| 命令 | 作用 |
|---|---|
| `npm start` | 启动工作台 |
| `npm run seed` | 重新载入示例数据（覆盖现有示例） |
| `npm run reset` | **清空**全部业务数据后重新载入示例 |
| `node tools/verify-ui.js` | 界面自检：跑七个页面 + 关键交互，输出截图与问题清单（见第六节） |
| `node tools/qa-review.js` | 对抗审查复测：64 项数据边界／提醒／安全／热点来源断言（见第六节） |
| `node tools/check-syntax.js` | 前后端全部模块的语法检查（前端为 ES Module，`node --check` 需转 `.mjs`） |
| `npm run hotspot:login -- douyin 2` | 命令行方式连接抖音账号（等价于页面上的「连接账号」） |
| `npm run hotspot:collect -- douyin 2` | 命令行方式采集热榜 |

界面里也可以重置：点击左下角账号 → **重置为初始示例数据**。
该操作会先向服务端申请一次性确认令牌，再由界面二次确认后携带令牌提交；
服务端不接受的、没有令牌或令牌被复用过的重置请求一律拒绝（见第七节）。

### 功能规则

- **个人任务**：来源为主营分配、排期自动生成、成员自建；可选关联版本／节点／目标／排期，也允许完全不关联的临时任务；截止日期选填，未设置不触发临期提醒。
- **状态与步骤**：未开始／进行中／已完成，成员标记完成立即生效、无需验收；步骤仅供负责人本人可见，只影响任务内部进度条。
- **个人顺序**：拖动或菜单上移／下移，只改自己的排序，不影响主营设置的任务信息。
- **目标进度**：按 `已完成任务数 ÷ 关联任务总数` 等权计算，进行中不计为已完成；无关联任务时显示「暂无关联任务」而不是 0%／100%。业务指标目标值单独展示，不冒充实际达成率。
- **节点状态**：有关联任务的节点由任务状态自动计算（全部完成即已完成，任务回退则节点同步回退）；无关联任务的节点由主营手动更新。
- **排期同步**：发布含制作／发布日期的排期，自动生成两项独立任务并可指定不同负责人；任务完成时排期阶段状态自动更新；编辑已发布排期会同步任务标题／日期／负责人，同时保留个人步骤与完成记录。
- **草稿与发布**：新草稿对成员完全不可见；发布后成员可见并收到「内容已更新」提醒；撤回后提醒同步移除。
- **已发布内容的修改**：编辑已发布的目标／节点／排期／卖点时，改动先进入「待发布修改」，成员在此之前一直看到旧版本；主营点「发布修改」才生效并只产生一次更新提醒。排期的修改在发布时才同步到相关任务（保留成员已填写的步骤与完成记录）。
- **草稿排期不派发任务**：无论新建还是编辑，未发布的排期都不生成成员任务；只有正式发布才按已填写的阶段生成独立任务。
- **排期是阶段数据的唯一来源**：发布修改后，任务截止日期一律与排期一致，**包括把日期清空**——清空后任务截止日期同步变空，不再因旧日期继续触发临期／逾期提醒；重新填写日期后同步恢复。
- **阶段被移除（日期与负责人都清空）时不静默丢数据**：任务尚未开始且没有步骤 → 直接移除；任务已有个人步骤或已开始处理 → 保留为独立历史任务，步骤与完成记录原样保留。两种情况都会在发布后如实告知主营。
- **撤回或删除整条排期同样保留个人投入**：规则同上，保留下来的任务会标明「原排期已撤回」或「原排期已删除」。撤回后排期正文对成员不可见，保留的只是成员自己的历史任务，**不再计入任何排期阶段状态**。
- **重新发布同一排期按当前阶段重新生成任务**，不会把历史独立任务重新挂回，也不会重复分配仍挂在该阶段上的任务。
- **操作前可预览后果**：点击撤回／删除排期前，界面会通过 `/api/schedule-impact` 取到「会移除几项、会为成员保留几项」并写进确认框；操作完成后提示实际保留／移除的数量。
- **一个任务必须有且仅有一个负责人**：只有日期、没有负责人的阶段不生成无主任务，并回报提示；排期只清空负责人但仍保留日期时保留原负责人，避免任务变成成员看不到的孤儿。
- **提醒**：仅站内显示；有截止日期的任务与节点在**前 1 天**提醒，逾期持续标识直至完成或改期；重复打开页面不会重复生成提醒。

## 四、界面改版说明（本轮）

用户反馈「字体感觉不对」，要求参考其提供的 UI 组件源码。`UI参考源码.txt` 是一个 React + Tailwind + shadcn 的「侧栏 + Chrome 风格标签页」组件。

### 结论：提取视觉规则改造现有页面，未直接集成 React 组件

**理由：**

1. **运行成本与产品阶段不匹配。** 这是要交付给约 8 位营销成员的单机体验版，要求 `npm start` 即可运行。直接集成需要引入 React、Tailwind、Vite 构建链与 Radix／framer-motion 等十余个依赖（数百 MB），且新增构建步骤；而现有后端是零依赖的静态文件服务。为一个已确认「先做单机可体验版」的项目引入构建链，收益不抵复杂度。
2. **组件中的 React 特性属于交互增强，不是视觉要求。** `framer-motion` 的 `layoutId` 标签背景动画、`Reorder` 拖拽、Radix 的 Tooltip／ContextMenu 都是行为层实现；其**视觉结果**（间距、圆角、色彩、字号层级、Chrome 标签的内凹圆角）完全可以用 CSS 等价复现，改版要求第 1 条要的正是这些视觉规则。
3. **迁移会带来无谓的回归风险。** 七个页面与全部业务规则已实现并通过自检；整体重写收益低、风险高。
4. **组件自带示例内容不可用。** `Acme Inc`／`Dashboard` 等按要求已替换为《天谕》手游营销工作台的实际导航与文案。

### 具体落实的视觉规则

| 项目 | 参考组件 | 本工作台 |
|---|---|---|
| 侧栏宽度 | 240px（收起 64px） | 240px |
| 品牌头 | `h-[52px] px-4 border-b`，logo `h-8 w-8 rounded-lg` | 一致 |
| 导航项 | `gap-3 px-3 py-2.5 rounded-lg`，图标 20px，文字 `text-sm font-medium` | 一致 |
| 选中态 | `bg-sidebar-accent` + 左侧 `w-1 h-5` 指示条 | 一致（指示条按说明书 §5 用蓝色表示选中） |
| 标签页 | `px-4 py-2.5 text-sm`，`min-w-[140px] max-w-[220px]`，选中 `bg-background rounded-t-xl` + 底部内凹圆角 | 一致，内凹圆角用 `radial-gradient` 实现 |
| 内容区 | 悬浮白卡 `rounded-3xl`（24px），`p-6` | 一致 |
| 页面标题 | `text-xl font-semibold` = 20px / 600 | 一致 |
| 正文字号 | `text-sm` = 14px（导航、标签页、按钮、表格） | 一致 |

### 字号层级（本轮的核心修正）

改版前大量使用 10.5–12.5px，可读性差。现按参考组件的 `text-xl / text-base / text-sm / text-xs` 统一为 CSS 变量：

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-title` | 20px | 页面标题 |
| `--fs-section` | 16px | 区块标题、弹窗标题 |
| `--fs-card` | 15px | 卡片标题 |
| `--fs-body` | 14px | 导航、标签页、按钮、表格、任务名、表单 |
| `--fs-sm` | 13px | 次要信息、日期、说明文字 |
| `--fs-xs` | 12px | 徽标、极次要信息 |

页面模板中已不存在硬编码 px 字号，全部引用上述变量，避免再次走样。行高由 11px 增至 13px，标签页与按钮高度同步加大。

字体族优先使用 `Microsoft YaHei UI`，兼顾 Windows 中文渲染与降级。

## 五、热点雷达：Playwright CLI 与真实接入边界

**本节如实说明已验证与未验证的部分，包括来源类型的准确性。**

### 已按用户要求改用 Playwright CLI

说明书 §4.7 指定使用 Playwright CLI 读取平台页面。本项目**已经实际使用 `playwright cli`**（不是直接调用 Node 库）。抖音公开热榜默认无需登录；小红书或用户选择登录抖音时才保存会话：

| 环节 | 实际执行的命令 |
|---|---|
| 连接平台（可选／小红书需要） | `node node_modules/playwright/cli.js cli -s=ty-<userId>-<platform> open --headed <平台登录页>` |
| 登录确认 | 用户完成登录后在工作台点「我已登录，开始搜索」；此时才检查登录 Cookie 并保存状态，不凭 Cookie 自动开始采集 |
| 保存登录状态 | `… cli -s=<session> state-save app/data/auth/<userId>-<platform>.json` |
| 采集 | 复用当前已打开的登录会话；若是以后单独刷新，才新开有头窗口并加载保存的状态；逐个 `goto <竞品搜索页>` → `eval` 取数 |
| 结束 | 五个竞品整轮处理完才执行一次 `close`；不会为每个关键词反复开关浏览器 |

会话名 `ty-<userId>-<platform>` 使「每个人 × 每个平台」各自一个浏览器会话，互不干扰；状态文件按同样维度隔离。已验证 CLI 可用（`node lib/hotspot.js` 会自检 `node_modules/playwright/cli.js` 是否存在，缺失时如实报「Playwright CLI 不可用」而不是静默失败）。

### 来源类型如实标注（本轮修正）

审查指出：小红书采集原本用 `/explore` 内容卡片与 `search/recommend` 建榜，却在界面标成「热榜」，属于来源不实。现已改为**每条热点都带 `source_kind`**，界面分开呈现：

| source_kind | 含义 | 界面呈现 |
|---|---|---|
| `hotlist` | 平台官方热榜排序 | 「抖音热榜」，带名次 |
| `explore` | 探索流/推荐内容，**不是**热榜排名 | 标题写明「小红书探索流（非官方热榜）」，并在页首常驻橙色提示 |
| `search` | 关键词搜索补充或自由搜索的结果 | 单独成表，标「非热榜排名」，不与热榜混排名次 |
| `competitor` | 竞品玩家讨论监控（小红书默认） | 按 5 个竞品分组，每竞品归纳最多 3 个讨论话题，与旧「热点」搜索数据隔离 |
| `competitor_filtered_v2` | 已过滤商业交易的竞品讨论 | 每竞品以 30 篇有效游戏内容讨论帖归纳 Top 3；旧版记录仍可识别为待刷新 |

- **抖音**：无需登录即可读取官方热榜页，标注为「平台热榜」。回退解析已收紧——只在榜单容器内取条目，并用导航词黑名单剔掉「首页/推荐/关注/热榜/全部分类」等杂项文本，避免把导航文字混进热榜。榜单话题关联视频的点赞、评论和发布时间可取得时单独标注，不冒充话题总量。
- **小红书**：**目前没有公开且稳定的官方热榜入口**。默认内容为**竞品玩家讨论监控**（`source_kind=competitor`），按竞品搜索真实玩家笔记并如实标注来源与字段；页面明示「不是官方热度排名，请勿当作平台榜单引用」。真实采集仍需体验者本人在官方页面登录后验证。

### 板块缺内容时自动补充（本轮实现）

- 热榜里没有内容的固定板块，会自动按**当期关键词**搜索补充，结果以 `source_kind=search` 入库并单独展示。
- 关键词不是一组永久死词：由「板块核心词 × 时令词」按周次轮换，随时间和板块变化。已验证同一板块间隔三周会取到不同关键词（如 `新赛季 爆款` → `新赛季 上榜`）。
- 单次刷新最多补充 4 个空板块，未补充的在连接状态里如实写明「另有 N 个空板块未补充」，不假装覆盖完整。
- 自由搜索与补充搜索的结果都带**可打开的原始来源链接**；平台未给出链接时回退到该话题的搜索页链接，不再返回空链接。

## 七、本地数据与安全

- 全部业务数据存放在 `app/data/app.db`（SQLite，WAL 模式），关闭应用与重启电脑后仍可读取。
- **平台密码不经过工作台任何表单。** 登录在平台官方页面完成。
- Playwright 登录状态文件可能包含可用于登录的 Cookie：按「用户 + 平台」隔离存放于 `app/data/auth/`，权限 `0600`，不写入日志，`app/.gitignore` 已排除，不会进入版本库或导出包。
- 热点结果与平台连接状态按账号隔离，只属于当前体验者，不进入团队公共数据区。
- 热点仅供个人查看灵感，**不会自动变成工作任务**。
- 演示数据与真实热点在存储上分离：演示数据由 `seed.js` 写入业务表；真实热点只写入 `trend_items` 且仅在真实采集成功后写入。真实账号登录前不会显示「已连接」。

### 写接口防护

本机服务同样会被浏览器里的其它网站请求到，因此不能只靠「只监听 127.0.0.1」。已加两道防线：

1. **来源校验**：写接口校验 `Origin`／`Referer` 必须是本服务地址，跨站请求直接 403。浏览器对跨站写请求一定会带 `Origin`，因此放行「无 Origin 的本机客户端」不会打开 CSRF 口子（该分支同时被下面的第 2 条约束）。
2. **只接受 JSON**：写接口要求 `Content-Type: application/json`。HTML 表单只能发出 `urlencoded`／`form-data`／`text/plain` 三种简单类型，因此跨站表单无法构造写请求，一律 415。

`POST /api/demo/reset`（会清空本机业务数据）在此基础上再要求**一次性确认令牌**：界面先调 `POST /api/demo/reset-token` 取令牌（有效期 2 分钟），用户在弹出的对话框里二次确认后才带令牌提交；令牌用后即废，重放或伪造一律 403。不存在「无令牌直接清库」的路径。

### 数据可见范围（体验版边界）

`GET /api/state?user=<id>` 按请求者角色整理返回内容：

- **成员视角**：只返回自己名下的任务与个人步骤，以及已发布的目标／节点／排期／卖点；不含任何草稿，也不含他人任务或步骤。
- **主营视角**：可看到全部任务名称与总体状态、全部草稿（用于发布），但**不返回他人的个人步骤**，符合说明书「总台不展示成员个人步骤」。
- 目标完成率、节点状态、排期阶段这类进度字段一律**先用全量任务在服务端算好，再按角色过滤**，避免过滤后数字失真。

这是体验版的数据可见范围，**不声称已实现真正的 8 人认证**；团队版仍需各自的账号与鉴权。

| `upsertScheduleTask` 用 `date \|\| existing.due_date` 更新旧任务，导致已发布排期**清空日期后个人任务仍保留旧截止日期**，旧日期还会继续触发临期／逾期提醒 | 日期改为无条件以排期为准（含清空）；负责人仅在排期给出时改写，只清空负责人而保留日期时保留原负责人并回报 |
| 「阶段日期和负责人都清空」时旧任务会以旧阶段数据继续误导成员 | 按个人投入区分：无步骤且未完成 → 移除；已有步骤或完成记录 → 保留为「原排期已移除」的独立任务（新增 `tasks.schedule_detached`），步骤与完成记录不丢 |
| 同步结果对主营不可见 | `publish_schedule` 返回 `syncReport`，界面如实提示「日期已清空」「任务已保留为独立任务」「只有日期没有负责人，未生成任务」等具体后果，不再只回一句「已发布」 |

### 对抗审查第 3 轮（历史记录丢失）

| 问题 | 修复 |
|---|---|
| `unpublish_schedule` / `delete_schedule` 调用 `removeScheduleTasks`，**硬删**任务与全部个人步骤，与说明书「已完成任务保留并可回看」冲突 | 改为 `retireScheduleTasks`：尚未开始且没有步骤 → 移除；已有步骤或已开始 → 转为独立历史任务并标明「原排期已撤回／已删除」。`removeScheduleTasks` 已彻底移除，不再有任何硬删路径 |
| 保留下来的任务可能仍被算作排期阶段状态 | 退役时清空 `schedule_item_id` 与 `schedule_stage`，`computeScheduleStages` 自然不再把它计入 |
| 重新发布排期可能把历史任务挂回或重复分配 | 阶段匹配只认仍挂在排期上的任务；历史任务已脱离，不会被复用。另加 `hasActiveStageTask` 兜底，重复发布不会重复分配同一阶段 |
| 主营看不到撤回／删除对个人任务的后果（个人步骤在主营视角被过滤，前端无从计算） | 新增服务端只读接口 `GET /api/schedule-impact?id=`，返回 `willRemove` / `willKeep` / 明细；确认框写明具体后果，操作后提示实际数量 |
| **顺带发现**：`delete_goal` / `delete_milestone` / `delete_schedule` / `delete_selling_point` 都不清除发布记录，成员会残留一条指向已删内容的「内容已更新」提醒且点不进去 | 四个删除动作统一补 `clearUpdate`，并加断言 |

### 更早修复

1. **撤回已发布排期后，其自动生成的个人任务仍然可见。** 与说明书「草稿对成员不可见」冲突。现在 `unpublish_schedule` 会一并移除该排期生成的任务。
2. **撤回发布后，「内容已更新」提醒残留。** 现在撤回目标／节点／排期／卖点时会同时清除对应的更新记录。
3. **进度条填充不显示**（`<span>` 行内元素不吃 `width`）。已在 CSS 中显式 `display:block`。

## 九、未完成与已知限制

单机体验版按说明书第 11 节**刻意不做**：8 人同时登录、内网服务器部署、站外消息推送、成员任务步骤监控、热点自动转任务、无人在线时后台抓取、真实营销 KPI 数据自动接入、手机端适配。

已知限制（按重要度排序）：

1. **抖音公开热榜已实测，小红书账号采集尚未端到端验证。** 抖音的视频指标只尝试榜单前 20 条，取不到的字段显示「未提供」；平台改版仍可能导致解析失效。
2. **小红书没有可核实的官方热榜入口。** 当前只能取探索流，界面已如实标注为「非官方热榜」。若必须按名次引用，需另行评估合规的数据来源。
3. **体验版的数据可见范围不等于真实鉴权。** API 已按请求角色过滤返回内容（成员看不到草稿与他人步骤），但角色由请求参数 `user` 决定，本机任何人都能构造 `user=1` 取得主营视角。真正的 8 人隔离需要账号与鉴权，属团队版范围。
4. **侧栏收起按钮为占位。** 参考组件有 240px ↔ 64px 收起动画，当前侧栏固定 240px，点击无效果。
5. 版本节点时间线在版本较多时横向滚动；未做「横向切换」的左右箭头控件，用筛选按钮替代。
6. 标签页顺序不可拖动（参考组件用 framer-motion `Reorder`），关闭与新增已实现。
7. **板块搜索补充每次最多覆盖 4 个空板块**，其余在连接状态里如实写明未补充，避免一次刷新耗时过长。
8. `data/app.db` 为二进制且含运行期数据。如需干净初始状态，用界面里的「重置为初始示例数据」或 `npm run reset`。

## 十、主要 API

服务仅监听本机，供前端调用。

| 方法与路径 | 说明 |
|---|---|
| `GET /api/state?user=<id>` | 读取该视角的状态快照，**已按角色过滤**（见第七节数据可见范围） |
| `POST /api/mutate` | 统一变更入口，body 为 `{ action, payload, user, viewUser }` |
| `POST /api/hotspot/login` | 用 Playwright CLI 打开平台官方页面等待本人登录，`state-save` 保存登录状态 |
| `POST /api/hotspot/collect` | `state-load` 恢复状态后采集，写库并自动补充空板块 |
| `POST /api/hotspot/search` | 关键词自由搜索（临时结果，不写库，返回可打开链接） |
| `POST /api/hotspot/disconnect` | 断开连接并删除本机登录状态文件 |
| `POST /api/demo/reset-token` | 签发一次性重置确认令牌（2 分钟有效） |
| `POST /api/demo/reset` | 清空本机业务数据并重新载入示例，**必须携带确认令牌** |
| `GET /api/schedule-impact?id=<id>` | 撤回／删除排期前的影响预览：会移除几项、会保留几项个人历史任务 |
| `GET /api/health` | 健康检查 |

所有 `POST` 写接口都要求 `Content-Type: application/json` 且来源为本服务（见第七节）。

`action` 取值包括：`create/update/delete_version`、`create/update/publish/unpublish/delete_goal`、`create/update/set_milestone_status/publish/unpublish/delete_milestone`、`create/update/publish/unpublish/delete_schedule`、`create/update/publish/unpublish/delete_selling_point`、`create/update/delete_task`、`set_task_status`、`reorder_tasks`、`create_self_task`、`add/update/toggle/delete_step`、`mark_update_read`、`mark_all_updates_read`、`delete_update_record`、`save/delete_topic`、`set_connection_status`、`clear_connection`。

其中 `update_*` 对**已发布**记录写入 `draft_json` 待发布区（返回后成员仍看旧版），对未发布记录直接改基础列；`publish_*` 会先应用待发布修改再置为已发布。

排期相关的三个动作会返回 `syncReport`（`created` / `removed` / `detached` / `dateChanged` / `assigneeKept` / `needsAssignee`），界面据此如实告知主营「日期已清空」「任务已保留为独立历史任务」等具体后果。

**删除与撤回都不会硬删个人数据**：`delete_*` / `unpublish_*` 会先按个人投入决定移除还是保留任务，再清除对应的发布记录，避免成员残留指向已删内容的「内容已更新」提醒。
